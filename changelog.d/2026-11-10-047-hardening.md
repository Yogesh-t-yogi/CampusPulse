# 047 — Hardening: rate limits, CORS from env, CSV de-duplication, dead code, README

## What changed
- **Rate limiting** (`config/RateLimitFilter.java`, in memory, per client IP, 1-minute window):
  - sign-in and register (POST `/api/auth/login`, `/register`): `RATE_LIMIT_AUTH`, default 10/min;
  - AI-heavy calls (POST `/api/ai/**`, `/api/syllabus/upload`, `/api/jobs/custom`, `/api/resume/**`, and
    GET report/recommendations with `refresh=true`): `RATE_LIMIT_AI`, default 30/min;
  - over the limit → HTTP 429 `{"message":"Too many requests. Wait a minute and try again."}`; 0 turns a limit off.
- **CORS** origins now come from `CORS_ALLOWED_ORIGINS` (comma-separated; default
  `http://localhost:5173,http://127.0.0.1:5173`). The old hard-coded Render URL is gone. Passed through docker-compose.
- **CSV job import** skips rows whose title + company already exist in that catalog (or appear twice in the file).
  Response has `imported`, `skipped` and a message; the Job catalog page shows the message.
- **Dead code removed:** `SkillMatchingController` (`/api/matching/jobs/..` keyword endpoint, unused by the UI),
  `SkillMatchingService`, `JobSearchProvider` interface.
- **README** rewritten: features, stack, one-command start, settings table, roles, tests, troubleshooting.
- `.env.example`: new optional settings documented.
- Tests: `RateLimitFilterTest` (limit, reset, per-IP, off), CSV re-import de-duplication test. 52 backend tests pass.

## How to test
1. Wrong password 11 times within a minute → the 11th says "Too many requests".
2. Job catalog → import the same CSV twice → second time "Imported 0 jobs; skipped N".
3. App still works from http://localhost:5173 (CORS).

## Risk
Low. If you open the frontend from another address (e.g. a LAN IP), add it to `CORS_ALLOWED_ORIGINS`.
