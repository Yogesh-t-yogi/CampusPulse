# AI extraction uses JSON mode and temperature 0; prompt-injection guard
- Type: feature (AI quality)
- Area: backend
- Commit: see `git log --grep "Use JSON mode"`

## Why
Syllabus structuring, job/resume skill extraction and recommendations asked the model
for JSON in plain text (temperature 0.2). Broken JSON caused failures or an extra
"repair JSON" call, and results varied between runs. Syllabus and job description text
went into prompts without telling the model to ignore instructions inside them.

## What changed
- `LlmService`: new `generateJson(prompt)` → temperature 0 + Groq
  `response_format: {"type": "json_object"}`. If the model rejects JSON mode (HTTP 400) it
  logs once, remembers, and retries without it. `generateResponse` unchanged.
- `SyllabusAiService`, `JobSkillAiService` (job description + resume),
  `AiRecommendationService` now call `generateJson`.
- Recommendations prompt now asks for `{"recommendations": [...]}` (JSON mode needs an
  object); parser accepts that or the old bare array (`parseRecommendations`).
- Syllabus and job-description prompts say the text is data only and to ignore
  instructions inside it (resume prompt already did).
- Test: `AiRecommendationParseTest` (object, array + code fences, missing list).

## How to test
1. Process a syllabus twice → same subjects/units/topics both times; backend log shows no
   "AI returned invalid JSON. Attempting repair".
2. Paste a job description twice → same skill list.
3. Report → Re-run analysis → Recommendations tab loads.
4. If the log shows "LLM rejected JSON mode", everything still works (plain mode).

## Risk / rollback
Temperature 0 makes wording of recommendations less varied (intended).
Revert the commit to undo.
