# 055 — LlamaParse reads scanned PDFs (plan 14, Phase C2)

## Why
The owner's "Llama API" key is a **LlamaParse / LlamaCloud** key (`llx-…`), not a Meta chat key. Changes
050–054 sent it to Meta's chat API → 401. LlamaParse is a document parser (PDF in, Markdown per page out).

## What changed
- New `LlamaParseClient` (Parse API v2): POST `/api/v2/parse/upload` (multipart `file` + `configuration`
  `{"tier","version":"latest","page_ranges":{"target_pages":"2,5"}}`) → poll GET `/api/v2/parse/{id}?expand=markdown`
  every 3 s → `markdown.pages[].{page_number, markdown, success}`. Errors explained (bad key/region, out of
  credits, failed job, timeout). Responses are read as text and parsed (Spring Boot 4's web client can't
  decode `com.fasterxml` JsonNode — found by the live check).
- `ScannedPageReader`: cache → **LlamaParse (one job for all missing pages)** → vision models
  (Gemini → Groq) for pages it didn't return → Tesseract if installed. Page method "llamaparse" is cached
  and shown on the upload screen as "read by LlamaParse".
- The "llama" chat slot is removed: chat order is now `gemini,groq` (`LLM_ORDER`). Text calls no longer try
  the LlamaParse key first.
- Settings: `LLAMA_CLOUD_API_KEY` (old `LLAMA_API_KEY` still accepted), `LLAMAPARSE_TIER`
  (default `cost_effective`, which OCRs), `LLAMA_CLOUD_BASE_URL` (EU: api.cloud.eu.llamaindex.ai),
  `LLAMAPARSE_TIMEOUT_SECONDS`. The owner's `.env` line was renamed (value untouched).
  `.env.example`, docker-compose and start-dev warnings updated.
- `/api/health/ai-providers` lists LlamaParse first.
- Tests: `LlamaParseClientTest` (5). 81 backend tests pass. Live check with the owner's key (tier
  cost_effective) on an image-only test page returned "# UNIT 2 Trees and Graphs"; the live test was removed.

## How to test
1. Restart the backend.
2. Delete the failed scanned syllabus and upload it again → progress → summary "read by LlamaParse".
3. Credits: check usage on the LlamaCloud dashboard (cost_effective ≈ a few credits per page).
